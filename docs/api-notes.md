# API and roster verification — 2026-11-10

Verified against the official [RuneScape 3 client API](https://developer.runescape.com/rs/). The documented embedded runtime is **Lua 5.4.8**. Runtime code uses Lua 5.4-compatible syntax and no filesystem, network, external Lua dependencies or blocking timers.

No manifest `entrypoint`, timer API, HTML UI, imaginary storage permission, close event or unload callback is assumed. Spin callbacks are explicitly unsubscribed. The plugin-lifetime Logic watcher observes visibility/identity and stays registered while enabled; it is not a spin timer. UI hooks on replaced views are released via destruction, and the root resize hook is explicitly removed. Plugin disabling is the host's own event/component teardown.

Roster verification: the initial 48 Soul Reaper entries were checked using indexed [Soul Reaper](https://runescape.wiki/w/Soul_Reaper#Bosses) and [assignment navigation](https://runescape.wiki/w/Template:Soul_Reaper) results. At the user's request, the pool now has **66 choices**, adding independent combat encounters, the intermediate Elite Dungeon/Sanctum bosses, raid bosses, Abomination and Char. Sources: [Bosses](https://runescape.wiki/w/Bosses#Combat_bosses), its accessible [Boss alias](https://runescape.wiki/w/Boss), and [Giant Mimic](https://runescape.wiki/w/Giant_Mimic). The original Croesus and Gate of Elidinis entries cover skilling bosses. Direct Bosses fetching was blocked; indexed results and the older cached alias were cross-checked. The complete added list and grouping policy are in README.md. These are a maintained snapshot, not a runtime wiki request or a guarantee about future game updates. Additional choices are not all valid Soul Reaper assignments.

PersistentDB explicitly recommends either character names or tracking IDs for character-specific data. Storage keys now have the form `reaper_roulette:character:name:<exact displayName>`, with schema 1 and a map of independent enabled/weight values. A missing, invalid or unnamed self entity never loads or writes a profile. Names are not normalized or substituted with a shared fallback. Renaming creates a new profile; reuse of a name on the same device reuses that name's profile. Older tracking-ID keys are left untouched, without guessing a name association. Valid unknown boss IDs are preserved across roster changes. Malformed/future-schema saves are kept untouched, with an error and Retry, rather than being silently overwritten.

Permission-error revision: the client recognized the earlier Tracking requirement but displayed “That permission could not be changed.” The updated manifest removes that requirement and identity no longer calls GetTrackingID or HasPermission. This avoids the failing permission path; the underlying client error has not been diagnosed. Refresh the manifest with `prf` while the plugin is disabled, then enable it again.

Blank-Settings revision: the screenshot showed only the first heading. The label helper attempted AlignTo with nonexistent ui.AlignMode.LEFT immediately after creating that heading. Correcting the host double to the documented enum reproduced a failure before any row could be created. The helper now uses TOPLEFT, and the native-boundary test completes Settings construction at the screenshot's panel size. The fix requires a source reload (`prl reaper_roulette`) in the actual client.
